# WUI D3D10 integration

`wui::d3d10::Renderer` draws immutable `DrawPacket`s into a host-owned
render target on a host-owned `ID3D10Device`. In D3D10 the device is also
the immediate context, so every call takes no separate context argument.
The renderer never creates windows, swap chains or threads, and never
presents. All calls happen on the caller's thread with external
synchronization.

Behavior described here is what `tests/renderers/d3d10_test.cpp` checks on
both a hardware adapter and WARP, Debug and Release. The common backend
conformance suite (`wui-conformance-d3d10-warp`) also renders every
fixture, gallery scene and replayed scenario and compares them with the
D3D11 WARP reference.

## Build

```bat
call out\native-env.cmd
cmake --preset win-d3d10-debug
cmake --build --preset win-d3d10-debug
ctest --preset win-d3d10-debug
```

`WUI_BUILD_D3D10=ON` adds the static `wui_d3d10` library. It links
`d3d10_1` and `d3dcompiler`. Shaders (`vs_4_0`/`ps_4_0`) are embedded from
`backends/renderer/d3d10_shaders.hlsl` at configure time and compiled with
`D3DCompile` in `create`, so `d3dcompiler_47.dll` must be loadable at run
time. No D3DX library is used.

## Device

```cpp
#include <d3d10_1.h>                 // before any d3d10.h include
#include <wui/backends/d3d10.hpp>

ID3D10Device1* device = /* D3D10CreateDevice1(..., D3D10_FEATURE_LEVEL_10_0, ...) */;
auto created = wui::d3d10::Renderer::create(device);
if (auto* error = std::get_if<wui::Error>(&created)) { /* report */ }
auto renderer = std::move(std::get<std::unique_ptr<wui::d3d10::Renderer>>(created));
```

- `create(nullptr)` returns `invalid_argument`.
- When the device implements `ID3D10Device1`, its feature level must be at
  least `10_0`. A 10.1-runtime device created at `9_3` returns
  `unsupported`. A device without `ID3D10Device1` is treated as 10_0.
- `<d3d10_1.h>` must be included before `<d3d10.h>`. The Windows SDK
  rejects the reverse order. `wui/backends/d3d10.hpp` includes `<d3d10.h>`.

## Rendering

```cpp
wui::d3d10::Target target{rtv, width_px, height_px};
if (auto error = renderer->render(packet, target)) { /* busy, invalid_*, ... */ }
// ... host Present ...
renderer->collect();
```

- The target must be a single-sample `R8G8B8A8_UNORM` or
  `B8G8R8A8_UNORM` 2D texture. Other formats return `unsupported`. The
  declared size must equal the texture's size and
  `round(viewport * scale)` of the packet. Otherwise the result is
  `invalid_argument`.
- A null packet returns `invalid_argument`. A packet that fails
  `validate_packet` returns `invalid_packet`. Both are rejected before
  any device state changes. A moved-from renderer returns `invalid_frame`.
- Blending is premultiplied `ONE`/`INV_SRC_ALPHA` on encoded SDR values,
  with no sRGB conversion. A straight-alpha texture is premultiplied in
  the pixel shader, and a premultiplied texture is sampled unchanged. Half-alpha
  red in either form resolves to the same pixel.
- Each batch clip becomes a scissor rectangle in physical pixels through
  the shared `backends/renderer/scissor.hpp` helper used by every
  renderer: edges within 1/1024 px of a pixel boundary snap to it, the
  rest are floored and ceiled outward, then clamped to the target. Batches
  with an empty scissor or zero indices are skipped.
- Each texture snapshot uploads once into its own immutable texture. The
  cache matches snapshot identity, not just `(handle, revision)`, so
  snapshots from different `TextureStore`s that share handle values never
  share a native texture. Rendering an older retained packet after a newer
  revision produces identical pixels.

## Frames in flight

Each successful `render` ends a `D3D10_QUERY_EVENT` and retains the packet
and its texture leases. With three submissions unretired, the next
`render` returns `busy`. `collect` polls the queries
in order with `GetData(..., D3D10_ASYNC_GETDATA_DONOTFLUSH)`. It never
blocks or flushes. It then releases texture revisions that no live snapshot
or unretired submission references. The host decides when to flush and
wait. The test flushes once, waits on its own event query and then calls
`collect`.

## State policy

`StatePolicy::restore` (default) captures and restores everything `render`
changes. A scope guard restores the state on success and on any error
after capture. Tests cover success and pre-capture rejections; no test
induces a late failure. The captured slots are:

- IA: input layout, vertex buffer 0 (stride and offset), index buffer
  (format and offset), primitive topology
- shaders: VS, GS (the renderer unbinds GS) and PS
- constants: VS constant buffer 0, PS constant buffer 1
- PS shader resource 0 and sampler 0
- RS: state, all viewports and all scissor rectangles, including a count
  of zero
- OM: blend state, blend factor and sample mask, depth-stencil state and
  stencil reference, all eight render-target slots and the depth-stencil
  view

The test binds a non-null host value in every slot, including two render
targets plus a DSV and two viewports and scissors. It checks each slot with
fresh `Get` calls after a successful render and after a rejected render. It
also checks a host with fully cleared state.

`StatePolicy::caller_restores` skips the capture. On return the UI
pipeline is still bound: the UI target alone with no DSV, the UI layout,
buffers, shaders, constant buffers, sampler, blend, rasterizer and
depth-stencil states, and one full-target viewport. GS and PS shader
resource 0 are null. The host rebinds what it needs.

## Recreation

`recreate(replacement_device)` replaces the device after the host stops
using the old one, for example after device removal. It drops all
device-bound objects, every pending submission and every uploaded texture.
It then rebuilds shaders and states on the replacement. Textures upload
again from the CPU snapshots of the next packets. On a replacement device
of the same driver type, retained packets render pixel-identically. The
test checks both revisions of the reference fixture this way, with one
submission still pending at the time of `recreate`. `recreate(nullptr)` returns
`invalid_argument`. A replacement below 10_0 returns `unsupported` before
anything is released, and the renderer keeps working on its current
device.

## Diagnostics

Debug test builds create every device with `D3D10_CREATE_DEVICE_DEBUG`
when `d3d10SDKLayers.dll` is installed. A deliberate SRV/RTV hazard shows
that the info queue records warnings. Each case then requires zero
warnings and errors. On Windows 10 the D3D10 runtime is layered on D3D11,
so validation messages name `ID3D11DeviceContext`.

## Not covered

- Real device removal. `render` and `collect` return `device_lost` when
  `GetDeviceRemovedReason` fails, but no test triggers it.
- Plain `ID3D10Device` (D3D10.0 runtime) devices. Every test device comes
  from `D3D10CreateDevice1`.
- Texture eviction after `collect`: D3D10 has no live-object report, and
  release is not measured.
- BGRA8 targets are accepted but only RGBA8 targets are rendered in tests.

## Common conformance suite

`tests/conformance/d3d10_backend.cpp` (`wui_conformance_d3d10`) creates a
`D3D10CreateDevice1` device at feature level 10_0 with
`D3D10_CREATE_DEVICE_DEBUG` (without it, and logged as a skipped debug
check, when the SDK layers are missing), a single-sample `R8G8B8A8_UNORM` target and a
staging readback texture, and counts `ID3D10InfoQueue` warnings and errors
after every group. CTest `wui-conformance-d3d10-warp` runs in every D3D10
preset; `wui-conformance-d3d10-hardware` also runs in the `win-all-*`
presets (`WUI_CONFORMANCE_HARDWARE=ON`).

Against the D3D11 WARP reference, D3D10 WARP is byte-identical in all 88
cases and the RTX 2080 Ti is within tolerance in all 88 (max channel
difference 2, no pixel over 8), with zero debug-layer messages. Details:
[D backend conformance](../validation/d-backend-conformance.md).
