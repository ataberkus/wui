# WUI D3D11 integration

Runnable consumer recipe for the A10 themed preview. Application owns the
window, device, message loop, and presentation. Backend code never owns the
main loop, never creates windows or swap chains, and never spawns threads.

## Modules

Enable text, Win32, D3D11, and the opt-in example. Core-only builds stay
portable; the example requires Windows.

Dependencies must already be staged and built from
[`third_party/lock.json`](../../third_party/lock.json). Ordinary configure
does not download them. The explicit preparation entry point is
[`tools/prepare_dependencies.py`](../../tools/prepare_dependencies.py):
`--verify` checks staged revisions without network access;
`--fetch` explicitly stages the locked sources and fonts;
`--build --config Debug` and `--build --config Release` prepare the matching
text-library prefixes. Run preparation in the same x64 developer environment.

```bat
call out\native-env.cmd
cmake --preset win-d3d11-debug -DWUI_BUILD_EXAMPLES=ON
cmake --build --preset win-d3d11-debug
```

`WUI_BUILD_EXAMPLES=ON` without Windows, text, Win32, and D3D11 fails at
configure time with
`WUI_BUILD_EXAMPLES requires Windows, text, Win32 and D3D11`.
The A10 example remains opt-in; the D3D9 and Vulkan probe presets do not
enable it. Pass the flag explicitly for A10 work.
A fresh core-only configure with `WUI_BUILD_EXAMPLES=OFF` still works.

The example links `wui_text`, `wui_win32`, `wui_d3d11`, `d3d11`, `dxgi`,
`d3dcompiler`, `user32`, `gdi32`, `shell32`, `ole32`, and `windowscodecs`.
It is a console-subsystem `wmain` binary so diagnostics keep stdout/stderr.
The example-local allocation override and validation controls are not public
library API.

## Fonts

Both Inter files and the license ship beside the binary. The build copies

- `assets/fonts/Inter-Regular.ttf`
- `assets/fonts/Inter-SemiBold.ttf`
- `assets/fonts/LICENSE.txt`

into `$<TARGET_FILE_DIR:wui_widget_gallery>/assets/fonts`. The host loads
fonts relative to the executable (`GetModuleFileNameW`), never the working
directory or an absolute source path. Running from another working directory
works; a missing font reports the exact failing path and exits 1.

### Display face

`make_text_service(FontFaces{regular, semibold, display}, textures)` adds an
optional third face for `FontRole::display`. An empty `display` falls back to
the semibold face and shares its glyph cache; a supplied face is copied,
validated and gets its own atlas entries. The two-span overload is the same as
an empty display face. `FontRole::body` uses the theme body size,
`heading`/`display` the heading size; `TextOptions::size` and
`TextStyle::size` override it per call. Shaped runs are cached in an MRU list
and the least recently used runs not held by a packet are evicted when the
cache is full, so long sessions with changing text keep a bounded footprint.

## Host order

1. Opt into per-monitor-v2 DPI awareness before creating the window
   (dynamically resolved; `SetProcessDPIAware` fallback; `ERROR_ACCESS_DENIED`
   means awareness was already set and the actual mode is reported).
2. Register `wui.A10.WidgetGallery`, create a `640x400` logical client,
   and construct `wui::win32::Adapter` on the owning thread.
3. Create the D3D11 device and swap chain with
   `D3D11CreateDeviceAndSwapChain`, requested hardware or WARP driver,
   feature level `11_0`, `BGRA_SUPPORT`, windowed two-buffer
   `R8G8B8A8_UNORM`, single-sample, `DISCARD`. Debug flag is tried first;
   retry without it only for `DXGI_ERROR_SDK_COMPONENT_MISSING`.
   Disable Alt+Enter, record adapter description/vendor/device/LUID and the
   `CheckInterfaceSupport` driver version or failure HRESULT, create the RTV
   from buffer zero, and create `wui::d3d11::Renderer` on the same device.
   Encoded-SDR baseline, no sRGB or MSAA conversion.
4. Load both Inter files, call `make_text_service(regular, semibold,
   textures)` with a shared 64 MiB `TextureStore`, and create `Context`
   with `Theme::dark()` and four packet slots. `Result` is consumed with
   `get_if<Error>`; `Status` is `optional<Error>`. No direct shaping or
   publishing in the host; `Frame::finish` publishes text.
5. `WndProc` forwards every message to `Adapter::process`; `true` returns 0,
   except that `WM_SYSKEYDOWN`/`WM_SYSKEYUP` still go to `DefWindowProc`
   (Alt+F4, Alt+Space, F10) and `WM_XBUTTON*` returns TRUE.
   `WM_DPICHANGED` applies the suggested RECT (adapter observes but returns
   false). `WM_SIZE` records client size and minimized state. `WM_CLOSE`
   sets a close flag; `WM_DESTROY` quits. Resize work is queued, never
   `ResizeBuffers` reentrantly. Adapter is reset while the HWND is valid;
   `GWLP_USERDATA` is cleared at `WM_NCDESTROY`.

### Hosting inside an existing window

`Adapter::process` returns true when the message became queued input:
pointer buttons (double clicks are presses), vertical or horizontal wheel,
keys including left/right modifiers and `WM_SYSKEY*`, text, IME composition,
or a focus cancellation. It returns false for messages it ignores or only
observes (`WM_SIZE`, `WM_SETCURSOR`, `WM_SETFOCUS`, `WM_DPICHANGED`). The
return value obliges nothing; it only reports whether the UI took the input.
The adapter never subclasses, never calls `DefWindowProc` and never calls a
previous window procedure.

A host that subclasses an existing window
(`SetWindowLongPtrW(GWLP_WNDPROC)`) calls `process()` first, then decides
itself whether to swallow the message or pass it on with `CallWindowProcW` —
for example, swallow mouse and keyboard input only while the menu is open and
forward everything else. The window must be Unicode
(`IsWindowUnicode`); the constructor rejects other windows, destroyed windows
and windows of other processes. Every key event carries
`InputEvent::native_key` (the virtual-key code, resolved to left/right for
modifiers), so keys without a `Key` name (OEM, numpad) can still be bound.

Threads: the `Adapter` may be constructed on any thread, but `process()` must
run on the HWND's owning thread; anywhere else it latches `invalid_frame`. One
other thread, typically the render thread, may concurrently call
`take_frame`, `status`, `set_target`, `clear_target`, `cancel_input`,
`set_composition_position`, `clipboard` and `set_clipboard`. Capture release
and IME caret positioning requested from that thread are applied on the next
`process()` call, so the window thread must keep pumping messages (clipboard
calls can also make Windows send `WM_DESTROYCLIPBOARD` synchronously).
Destroy the adapter on the window thread if it may hold mouse capture.

When the swap-chain size differs from the client rectangle, call
`set_target(width, height, scale)`: pointer positions are scaled from client
pixels into that extent and `take_frame` reports `{0, 0, width / scale,
height / scale}` with `scale` instead of the window DPI. `clear_target()`
restores client-rectangle and DPI behavior. Call `cancel_input()` whenever
input stops being routed to the UI (for example when hiding the menu): it
queues `focus_lost` and forgets held buttons, modifiers and partial text;
capture is released on the next `process()`.

## Frame, ownership, and backpressure

Pump messages, apply pending resize, check host and adapter errors, collect
completed renderer work, then advance one transaction:

- `take_frame(dt)` once only when no input or packet is pending.
- `begin_frame`; `busy` retains the same input.
- `build_gallery`, close scopes, `finish`; retain the packet until render
  succeeds. Never rebuild or replay input after a `busy`.
- Clear the RTV to `Theme::dark().canvas`, `render` with physical client
  dimensions and `StatePolicy::restore`, drop the host reference, `collect`,
  then `Present(1,0)`.

A `busy` iteration pumps messages and waits up to 1 ms
(`MsgWaitForMultipleObjectsEx`); no tight spin. The host may `Flush` once on
entering a busy episode; `collect` itself never flushes and polls with
`D3D11_ASYNC_GETDATA_DONOTFLUSH`. Steady-clock `dt` resets after suspension.

Physical dimensions are logical dimensions times packet scale. Validation
scales simulate DPI without falsifying `WM_DPICHANGED`; interactive mode
uses the untouched adapter frame.

## C1 layout, style, and custom paint

- `frame.row(key, columns)` resolves fixed/share columns against the current
  container width. Open one `row.cell()` at a time; scopes close in LIFO order.
  `frame.available_width()` returns the resolved width in the current cell.
  Unused trailing declared cells are allowed.
- `frame.scroll(key, viewport_height)` clips its children and persists a
  keyed offset; `frame.spacer(height)` reserves content height.
  `visible_rows(count, row_height, offset, viewport_height)` returns the
  half-open range of fixed-height rows to emit. Inner scroll views hand unused
  wheel movement to enclosing scroll views. These APIs do not virtualize
  variable-height rows.
- `frame.description(text, {.color = color})` wraps at explicit newlines,
  ASCII word breaks, then sanitized grapheme boundaries at the resolved cell
  width. An oversized first grapheme advances whole under the cell clip.
  `frame.text(text, {.wrap = true})` opts the ordinary text call into wrapping;
  the one-argument call remains unwrapped. Packet semantics retain caller text.
  `TextOptions::align` (`Align::start`, `center`, `end`) places each line in
  the row; `WidgetOptions::label_align` does the same for a button label
  (default `center`). A line wider than its room starts at the left edge.
- `frame.custom(key, label, height)` reserves a row and returns owned
  `{id, bounds, clip, behavior}`. It uses button activation and records one
  accessible semantic. Borrow `frame.canvas()` only during the active frame;
  balance `push_clip(item.clip)`/`pop_clip()` around explicit paint.
  `gradient` and `border` use the existing white texture and premultiplied
  vertex colors; invalid paint fails `finish()`.
- `auto scope = frame.style({.accent = color})` affects nested controls until
  scope destruction without changing `Context::theme`. Resolution order:
  theme, enclosing scopes (inner wins), `WidgetOptions::variant` (`normal`,
  `prominent`, `quiet`), then `WidgetOptions::style`. Optional override tokens
  are `control`, `text`, `accent`, and `focus`. Focus rings remain distinct from
  hover/selection; reduced motion snaps transitions without changing hit
  geometry. `frame.icon_button(key, accessible_label, texture, options)` shares
  button activation, uses the theme control height (36 logical pixels at dark
  defaults, 28 compact), and requires a nonempty accessible label. Keep its
  `TextureHandle` valid until submitted packet leases retire.

The shipped A10 gallery still displays the original foundation controls;
the complete C-series gallery is a separate cutover.

## C2 navigation, selection, and feedback

- `frame.tabs`, `frame.radio`, and `frame.dropdown` bind `Choice<T>{value, label}`
  to caller-owned values, not option indexes. Choices use stable qualified IDs;
  unknown values report nonfatal diagnostics via `Context::diagnostics()`
  (up to 64 frame-owned entries). No model is silently changed.
- Dropdown options render in one root-clipped popup above ordinary content.
  While open, the popup routes pointer, wheel, Escape, arrow keys, and
  Enter/Space without activating controls behind it. Tooltip overlays paint
  after popup options.
- Call `frame.tooltip(owner_key, message)` after emitting the keyed owner in
  the **same ID scope**. The owner must remain enabled and hovered for 450 ms;
  delay uses the full validated `FrameInput.dt_seconds`, not the animation
  timestep. Leaving, disabling, or omitting the owner resets its timer. A
  missing earlier owner reports a nonfatal diagnostic. The root-clamped tooltip
  has `Role::tooltip`, copies its label into the packet, and never captures
  pointer or focus.
- `frame.validation(message)` emits ordinary wrapped flow text with invalid
  ink and `Role::validation`; it cannot take focus. Pass
  `WidgetOptions{.invalid = true}` to mark an associated control's border and
  semantic invalid state without changing its ID, value, or focus ring.

## C3 value controls

- `frame.slider(key, label, value, min, max, options)` accepts `float&` or
  `int&` values. It changes the caller's model synchronously on pointer
  press/drag (capture continues outside the track), or on focused Left/Right
  and Home/End. Integer arrows step by one; float arrows step by 1% of the
  range. Values clamp to the inclusive endpoints. Invalid/nonfinite float
  values or bounds, or any `min >= max`, invalidate the frame before mutation.
  The packet owns a formatted `Role::slider` semantic value; focus and invalid
  outlines remain distinct.
- `frame.text_input(key, label, value, options)` edits a `std::string` while
  focused. Grapheme-aware Left/Right, Home/End, Shift selection, Backspace,
  Delete, Ctrl+A and Ctrl+Z are applied in order and published to `value`
  synchronously. Ctrl+C/X/V use `ContextDesc::clipboard`; `win32::Adapter`
  implements `IClipboard` and can be passed there. Without a clipboard
  service, or when the service fails, the shortcut leaves the draft
  unchanged and records an `unsupported` (or the service's) error in
  `Context::diagnostics()` rather than invalidating the frame.
- `frame.numeric_input(key, label, value, min, max, options)` accepts
  `double&`, `float&` or `int&` and shares the text editor and clipboard
  behavior above, but `value` always holds the last committed number. The
  focused draft may be invalid (`""`, `"-"`, `nan`, `inf`, trailing bytes,
  overflow or out of range) and is shown with invalid ink and an invalid
  semantic without touching the model. Plain Enter, or focus loss by Tab,
  click or window deactivation, commits a draft that parses entirely as a
  finite value inside the inclusive bounds; otherwise focus loss restores the
  committed text. Escape cancels the draft and composition. Bounds and the
  incoming value must be finite with `min <= max` (equal bounds allow that
  one value) or the frame is invalidated. The `Role::numeric_input` semantic
  value is the displayed draft.
- `WidgetOptions::placeholder` replaces the label as the hint shown in an
  empty `text_input`, `numeric_input` or `text_area`, and in a `data_grid`
  with no rows; the accessible label is unchanged.
- `frame.text_area(key, label, value, height, options)` is a multi-line
  editor (`height` 0: four body lines). It word-wraps at the box width,
  scrolls internally with the wheel and keeps the caret line visible. On top
  of the `text_input` keys, Enter inserts `'\n'`; Up/Down and Page Up/Page Down
  move by visual line keeping the caret column; Home/End go to the visual line
  edges and Ctrl+Home/End to the whole text. A press places the caret and a
  drag selects. Ctrl+V turns CRLF and CR into `'\n'`. The semantic is
  `Role::text_area` with the draft as value, and the IME caret follows the
  painted caret.
- `frame.data_grid(key, label, columns, rows, cell, selected, sort, height,
  options)` shows `GridColumn{title, width, min_width, sortable}` headers over
  `rows` virtualized rows; `cell(row, column)` is called only for visible
  cells and may return `std::string`, `std::string_view` or `const char*`.
  A header click (or Enter/Space on a focused header) sets `GridSort` to
  ascending, then toggles it; the caller sorts its rows when
  `GridResult::sort_changed`. Dragging a header's right edge resizes the
  column (widths are kept per grid). Click, Up/Down, Home/End and Page
  Up/Page Down set `selected` (`selection_changed`); Enter reports
  `activated`; Left/Right and the horizontal wheel scroll the columns.
  Semantics: `Role::grid` (value: selected index), one `Role::grid_header`
  per visible column (value `ascending`/`descending` when sorted) and one
  `Role::grid_row` per visible row labelled by its first cell. The scroll
  indicator is not draggable and double-click does not activate.

## E1 host embedding (overlay menus)

These APIs cover what an in-process overlay menu needs on top of the C
series. They stay within the spec: one active popup chain per context, no
docking, no native multi-window, SDR output only.

- **Input.** `InputEvent::button` (`left`, `right`, `middle`, `x1`, `x2`),
  `wheel_x`, `alt`, `super` and `native_key` extend the event. `Key` covers
  letters, digits, F1–F12, Insert, Page Up/Down and left/right modifier keys.
  Only the left button drives focus, capture, activation and dragging; a right
  press and release on the same target sets `Behavior::secondary_activated`
  without moving focus. `frame.events()` exposes the frame's raw validated
  events (key binding capture, extra buttons), `frame.pointer()` the last
  pointer position, and `frame.take_wheel(rect)` consumes the wheel steps
  over `rect` as `{x, y}` so enclosing scroll views do not also scroll.
  `DragResult` actions carry `position_y` for 2D drags.
- **Placement.** `frame.custom_at(key, label, rect)` is `custom` at an explicit
  rectangle and does not advance the flow. `frame.region(key, rect)` opens a
  clipped flow at an explicit rectangle (side bars, absolute layouts) and
  leaves the parent flow untouched. `frame.next_rect(height)` previews the
  next flow rectangle without taking it; `frame.viewport()` returns the frame
  viewport.
- **Popups.** `frame.open_popup(key)` opens a keyed popup (replacing any open
  dropdown list); `if (auto p = frame.popup(key, {.anchor = r}))` emits its
  content each frame. Non-modal popups sit below the anchor (above if it does
  not fit), clamped to the viewport, at least six control heights wide;
  `.width` overrides. Height is the content measured on the previous frame.
  `.modal = true` centers the popup and dims the viewport. While a popup is
  open, widgets outside it are inert; a press outside or Escape closes a
  non-modal popup and is not delivered below, a modal popup only closes
  through `frame.close_popup()`. `popup_open(key)` reports state; a popup not
  emitted during a frame closes when that frame finishes. Popups share the
  single popup slot with dropdowns, so a dropdown inside a popup cannot open
  its list; use radio/tabs or a nested custom list there.
- **Layers.** Popup and `frame.overlay(key, rect)` paint is detached from its
  enclosing panels: it is not clipped by them and paints after all main
  content (nested layers above their parents). Dropdown lists and text
  tooltips paint above layers. `frame.tooltip_due(owner_key)` reports the
  shared hover delay for an earlier widget so callers can draw rich tooltips
  with `overlay`.
- **Text and shapes.** `frame.measure_text(text, style)` and
  `frame.draw_text(top_left, text, style)` shape with `TextStyle{role, size,
  color}` for custom paint. `canvas.polygon(points, color)` fills a simple
  (possibly concave) polygon of 3–512 points with an antialiased fringe;
  self-intersecting input fails `finish()`. `canvas.gradient(rect, tl, tr, br,
  bl)` interpolates four corner colors bilinearly.
- **Disabled scopes.** `frame.style({.disabled = true})` disables every widget
  and custom item emitted inside the scope (`CustomItem::enabled` reports it).
- **Color picker.** `frame.color_picker(key, label, color, {.alpha, .size})`
  edits a straight-alpha `Color` with a saturation/value square, hue bar and
  optional alpha bar (pointer drag; focused Left/Right/Home/End). Hue survives
  achromatic colors. The `Role::slider` semantic value is `#RRGGBBAA`.
- **Transparent overlays.** A theme whose `canvas` alpha is 0 skips the root
  fill, so a separate `Context` can draw an in-game overlay (ESP, HUD) over
  the game image without clearing it. Use one `Context` per independently
  laid-out surface; overlapping movable windows are not provided — keep one
  menu surface and move it by changing the frame viewport, or drag a
  `region`/`custom_at` rectangle.

## Resize, minimize, occlusion, and recreation

- Minimized or zero-size windows do no render or present work; `collect`
  may still retire.
- Resize discards an unsubmitted finished packet (geometry targets old
  dimensions) without replaying input. A begin-busy input updates its
  viewport and rescales pointer coordinates, preserving order.
- Before `ResizeBuffers`, unbind render targets, release the RTV and every
  capture or backbuffer reference, clear staging, resize to the actual
  nonzero `GetClientRect` size, and rebuild the RTV. `GalleryState`,
  `Context`, fonts, and the texture store survive.
- `DXGI_STATUS_OCCLUDED` suspends rendering with throttled
  `Present(0,DXGI_PRESENT_TEST)` until visible. Other failures terminate
  with operation and HRESULT, never infinite retry.
- Device removal or `device_lost` triggers one recovery for that event:
  drop the pending packet, unbind and clear the old context, release old
  swap-chain resources, create a fresh device and swap chain for the same
  HWND and driver, then `Renderer::recreate`. Healthy-device recreation
  issues an event query, flushes once, and waits up to 5 s with message
  pumping. Controlled recreation is not hardware-removal proof.

## Textures, scissor, and conformance

- Native textures are cached by snapshot identity plus handle, revision,
  extent and alpha mode. A host with several `TextureStore`s can reuse
  handle values safely; equal handles from different stores never share
  a native texture.
- Batch clips become scissor rectangles through the shared
  `backends/renderer/scissor.hpp` helper, so all five renderers select the
  same pixels. Edges within 1/1024 px of a pixel boundary snap to it; the
  rest are floored and ceiled outward and clamped to the target.
- D3D11 WARP is the reference for the common backend conformance suite
  (`tests/conformance/`, CTest `wui-conformance-d3d11-warp`): 88 fixtures,
  gallery scenes, stress workloads and replayed scenario checkpoints, plus
  lifetime and recreate checks with the debug layer counted. The
  `win-all-*` presets also run every other renderer and the RTX 2080 Ti,
  then `wui-conformance-compare` checks them against this reference. See
  [D backend conformance](../validation/d-backend-conformance.md).

## Render-target formats

`Renderer::render` validates the render-target *view*
(`ID3D11RenderTargetView::GetDesc`), not only its texture. The view must be a
`D3D11_RTV_DIMENSION_TEXTURE2D` view of a single-sample texture;
`Target::width/height` must equal the view's mip-slice size (mip 0 for a back
buffer) and `round(viewport * scale)` of the packet.

| View format | Output |
|---|---|
| `R8G8B8A8_UNORM`, `B8G8R8A8_UNORM` | encoded SDR values stored unchanged (reference path) |
| `R10G10B10A2_UNORM` | same encoded values, quantized to 10 bits; 2-bit alpha |
| `R8G8B8A8_UNORM_SRGB`, `B8G8R8A8_UNORM_SRGB` | decoded to linear in the pixel shader, re-encoded by the hardware |

Typeless textures (`R8G8B8A8_TYPELESS`, `B8G8R8A8_TYPELESS`,
`R10G10B10A2_TYPELESS`) are accepted when the view uses a format above. Every
other view format — notably `R16G16B16A16_FLOAT` (scRGB/HDR) — and every
multisampled or array view returns `ErrorCode::unsupported` with the
`DXGI_FORMAT` number or sample count in the message, before any device state
is touched (both state policies). HDR output stays out of scope (spec §10).

For `_SRGB` views a second pixel shader from the same HLSL unpremultiplies,
applies the exact sRGB decode and premultiplies again, so opaque pixels store
the UNORM reference values within one 8-bit step. Translucent edges blend in
linear light there and differ slightly from the UNORM reference.

Hooked hosts: a Present hook that creates its RTV over the back buffer with a
NULL view desc works for every SDR flip-model buffer format above; an `_SRGB`
view of an 8-bit buffer also works. An HDR `R16G16B16A16_FLOAT` swap chain
makes `render` return `unsupported`; the host must then composite from its own
SDR texture or skip drawing.

## CLI

```bat
out\win-d3d11-debug\wui_widget_gallery.exe --driver warp --validate out\validation\a\debug-warp
out\win-d3d11-release\wui_widget_gallery.exe --driver warp --measure out\measure\c\release-warp
out\win-d3d11-release\wui_widget_gallery.exe --driver warp --measure out\measure\c\release-warp --workload controls1000
out\win-d3d11-release\wui_widget_gallery.exe --driver hardware --validate out\validation\a\release-hardware
out\win-d3d11-release\wui_widget_gallery.exe --driver hardware
```

`--driver hardware|warp` defaults to hardware. `--validate` and `--measure`
conflict; `--workload gallery|controls100|controls1000|virtual10000`
(default `gallery`) is accepted only with `--measure`; `--help` prints usage. Unknown, missing, duplicate, or
conflicting arguments exit 2. Initialization, runtime, or validation
failures exit 1; successful validation, measurement, or ordinary close
exits 0. Hardware creation failure is explicit, never silent WARP fallback.
Exceptions and `bad_alloc` are caught at `wmain`; nothing crosses `WndProc`.

`--validate` uses programmatic app-HWND input and a simulated four-scale
matrix; it does not change OS DPI or prove manual input. It drives the
complete gallery: every pointer target comes from the current frame's
`Semantic` role, label and bounds (scrolling the page with real
`WM_MOUSEWHEEL` until the control is visible), never from fixed pixels. Its
report (`validation.txt`) has one `PASS`/`FAIL` line per scenario, including
`scenario-01` through `scenario-10` for the ten acceptance scenarios, and PNGs
under `scale-*/` and `scenarios/`. Observed limits:

- Startup shows the Controls section; only `Notifications` and `Restore
  defaults` are pinned, never the semantic count or order.
- Synthetic `WM_MOUSEMOVE` does not move the real cursor, so the validator
  cancels the window's `TME_LEAVE` tracking after each move; otherwise the
  system's `WM_MOUSELEAVE` would end hover at an arbitrary frame. The Win32
  adapter itself ignores `WM_MOUSELEAVE` while a press is captured.
- Text is typed with `WM_CHAR`/`WM_KEYDOWN`. No IME is driven natively, and
  the interactive clipboard is never touched; IME preedit, result and
  cancellation through `Adapter` and `Context` are covered by `wui-win32`, and
  clipboard by the elevated `wui-win32-clipboard` suite.
- The resize matrix uses 800x600, 1280x720 and 1920x1080 physical clients at
  simulated scales 1, 1.25, 1.5 and 2 (the gallery raises the window's maximum
  tracking size so 1920x1080 fits on any monitor); actual OS DPI is reported
  separately.
- Duplicate choice values cannot be expressed by the fixed gallery source and
  remain covered by the core choice tests; the native run exercises a missing
  value.

`--measure` writes `measurement-<workload>.txt` plus one CSV per accepted
batch. Each batch resets the scenario, applies the workload's theme, prewarms
all four packet slots by building that same workload with the same viewport,
scale and `dt`, presents 120 warmup frames, then records exactly 300
successfully presented real-app frames (420 Presents). Any resize, DPI, input,
model, suspension or recovery interruption discards and restarts the whole
batch (at most five attempts). Every sample must keep the prewarm semantic
count and scale.

- `gallery` (the default) measures the Controls section at logical 1280x720
  and at 800x600 for simulated scales 1, 1.25, 1.5 and 2. It is the hard
  zero-allocation gate: `cpp_alloc_calls` and `cpp_alloc_bytes` must be zero
  in every warmed sample, else the report gets a frame-indexed
  `FAIL gallery zero-new batch=... frame=N` and the process exits 1; otherwise
  `PASS gallery zero-new 300/300 presented frames batch=...`.
- `controls100` (10x10 labeled buttons), `controls1000` (40x25 grid of 32x28
  icon buttons, compact theme with zero gap) and `virtual10000`
  (`visible_rows` over 10,000 persistent rows on a 28px pitch) run once at
  logical/physical 1280x720 and report allocations without a gate.

The allocation counter and CPU clock cover the host `begin_frame` through
`finish` only, counting UI-thread C++ `new` requests (not `malloc`, other
threads or driver allocations). GPU time comes from D3D11
`TIMESTAMP_DISJOINT` plus two `TIMESTAMP` queries around the UI renderer
submission, read asynchronously afterwards; a disjoint or unavailable query is
reported as such, never replaced by Present time. Each CSV row also records
vertices, batches, `Context::statistics()` retained/peak bytes and the process
peak working set. Results and observed limits are in the
[C gallery report](../validation/c-gallery-report.md); the earlier five-widget
evidence remains in the [A10 validation report](../validation/foundation-report.md).
