# WUI D3D9 integration

`wui::d3d9::Renderer` (`include/wui/backends/d3d9.hpp`, target `wui_d3d9`)
draws immutable `DrawPacket`s into a host-owned render-target surface on a
host-owned `IDirect3DDevice9`. The host owns the scene, the target and
presentation. The renderer never calls `BeginScene`, `EndScene` or
`Present`, and never creates windows, devices or threads. All calls are
serialized on the host's device thread. Tests: `wui-d3d9-chunks`
(device-free), `wui-d3d9` (native HAL) and `wui-conformance-d3d9-hardware`.

## Build

```bat
call out\vulkan-env.cmd
cmake --preset win-d3d9-debug
cmake --build --preset win-d3d9-debug
ctest --preset win-d3d9-debug
```

`out\native-env.cmd` also works; `vulkan-env.cmd` calls it and only adds
the Vulkan SDK. `WUI_BUILD_D3D9=ON` adds the static `wui_d3d9` library,
which links `d3d9` and `d3dcompiler`. `backends/renderer/d3d9_shaders.hlsl`
is embedded at configure time and compiled with `D3DCompile`
(`vs_3_0`/`ps_3_0`, strict) in `create` and again in `after_reset`. No D3DX
is used. The presets also enable `WUI_BUILD_TEXT`, which adds the gallery
test and the conformance suite.

## Device requirements

```cpp
#include <wui/backends/d3d9.hpp>   // includes <d3d9.h>, defines NOMINMAX
auto created = wui::d3d9::Renderer::create(device);   // IDirect3DDevice9*, HAL
if (auto* error = std::get_if<wui::Error>(&created)) { /* report */ }
auto renderer = std::move(std::get<std::unique_ptr<wui::d3d9::Renderer>>(created));
```

- `create(nullptr)` returns `invalid_argument`. A non-HAL device returns
  `unsupported`.
- Caps must report vs_3_0/ps_3_0, `MaxVertexIndex >= 2`,
  `MaxPrimitiveCount >= 1`, scissor test, `ONE`/`INVSRCALPHA` and separate
  alpha blending, and textures of at least 4x4 with alpha and linear
  min/mag filtering. `SQUAREONLY` is rejected, and `POW2` requires
  `NONPOW2CONDITIONAL`. A missing cap returns `unsupported` naming it. Each
  rule has a synthetic `D3DCAPS9` test.
- An `A8R8G8B8` texture must pass `CheckDeviceFormat` on the current
  display-mode format, and an `EVENT` query must be creatable. Otherwise the
  result is `unsupported`.
- The renderer cannot be copied or moved.

## Rendering

```cpp
device->BeginScene();   // tests always wrap render in the host's scene
auto error = renderer->render(packet, {surface, width_px, height_px});
device->EndScene();
// ... host Present ...
renderer->collect();
```

- Target: a non-null, single-sample `A8R8G8B8` or `X8R8G8B8`
  `D3DUSAGE_RENDERTARGET` surface on the renderer's device. A wrong format,
  MSAA or usage returns `unsupported`. Its size must match the declared size
  and `round(viewport * scale)`. A size mismatch or a surface from another
  device returns `invalid_argument`.
- A null packet returns `invalid_argument`. A packet that fails
  `validate_packet` returns `invalid_packet`. Every check runs before any
  device state changes. A packet with no indexed batches succeeds without
  touching state or taking a frame slot.
- Blending is premultiplied `ONE`/`INVSRCALPHA` (`ADD`) for color and
  separately for alpha. sRGB write and sRGB sampling are off, so values
  stay encoded SDR. The pixel shader premultiplies straight-alpha texels and
  samples premultiplied ones unchanged. Half-alpha red in either form over
  black gives (128, 0, 0) within 3. Sampler 0 is bilinear, clamped, without
  mips. Depth, stencil, culling, fog, alpha test and lighting are off.
- The vertex shader applies the pixel-center correction, shifting by half
  a physical pixel in clip space (`-1/width`, `+1/height`). It does not leak
  into widget coordinates, clips or scissors. At scales 1 and 2 the test
  probes interior colors, both sides of a clip edge, and bilinear checker
  texels at known pixel centers.
- Batch clips go through the shared `physical_scissor` helper
  (`backends/renderer/scissor.hpp`). It snaps edges within 1/1024 px of a
  pixel boundary, then floors and ceils outward and clamps to the target.
  Chunks with an empty scissor are skipped.
- Each texture snapshot uploads on first use into its own `D3DPOOL_MANAGED`
  `A8R8G8B8` texture. The cache key includes snapshot identity, so equal
  handles from different `TextureStore`s never share a texture. The test
  draws white, then red with the same handle and revision, then white
  again. Older retained revisions re-render correctly. A snapshot over
  `MaxTextureWidth`/`MaxTextureHeight` returns `unsupported`.

## Frames in flight

Each `render` that draws issues a `D3DQUERYTYPE_EVENT` query and retains
the packet and the textures it used. With three submissions unretired,
`render` returns `busy` before it looks at the packet. `collect` polls the
queries in order with `GetData(nullptr, 0, 0)` and never flushes or waits.
It releases retired submissions and drops cached textures whose snapshot
has expired. If three submissions remain, it returns `busy`. In the test,
three renders succeed and a fourth returns `busy`, and `collect` returns
within 2 s. After a `GetRenderTargetData` readback, `collect` succeeds and
the packet lease is released.

## State policy

`StatePolicy::restore` (default) captures a `D3DSBT_ALL` state block. It
also captures render targets 0 to `min(NumSimultaneousRTs, 4) - 1`, the
depth-stencil surface, the viewport, the scissor and the world, view and
projection transforms. A scope guard applies the block and then those
values, on success and on any error after capture. The test binds host
render targets, a depth surface, viewport, scissor and world transform. It
also binds texture 0, the shaders, stream 0 (offset 16), indices, the
declaration, cull, blend, sampler and shader-constant state. It checks them
after a successful render and after a late failure, an oversized texture
rejected mid-render.

`StatePolicy::caller_restores` skips the capture. On return the target is
RT0 with no depth-stencil, and the viewport covers the full target. The
renderer's states, declaration, shaders, constants, last scissor and
texture, and dynamic vertex/index buffers also stay bound. Tests check only
RT0 and the stream/index bindings. The host rebinds what it needs.

## Reset lifecycle

```cpp
renderer->before_reset();      // host has stopped submitting UI work
// host: release its own DEFAULT-pool surfaces (UI target, readback)
device->Reset(&presentation);
if (auto error = renderer->after_reset()) { /* device_lost: retry later */ }
```

- `before_reset` is idempotent and drops in-flight submissions without
  polling. It always sets stream 0 and the index buffer to null, even when
  the host owns them. The declaration, shaders and texture 0 are unbound
  only when they are the renderer's own. It then releases all its buffers,
  shaders and textures.
- `after_reset` returns `invalid_frame` without `before_reset`, and
  `device_lost` while `TestCooperativeLevel` still reports a lost device.
  Otherwise it rebuilds the shaders. Buffers regrow and textures upload
  again from later packets.
- `render` and `collect` return `device_lost` while a reset is pending,
  when `TestCooperativeLevel` reports a lost device, and after a failed
  `Issue` or `GetData` until the reset hooks run.

The tests run ten real `Reset` cycles, changing back-buffer size and scale,
with `render` gated between the hooks. With text enabled, old and new
gallery atlas revisions re-render pixel-identically across ten more cycles.
A third test leaves the renderer's pre-growth buffers bound and calls
`before_reset`, after which `Reset` succeeds.

## Chunking

`make_chunks(packet, max_vertices, max_primitives)` is public and device-free.
`render` calls it on every call with `min(65535, MaxVertexIndex + 1)` and
`MaxPrimitiveCount`.

- The packet is validated first (`invalid_packet`). The vertex limit is
  clamped to 65,535, so 16-bit indices stay at or below 65,534. Limits
  under 3 vertices or 1 primitive return `capacity`, as does allocation
  failure.
- Triangles are walked in order with `base_vertex` applied. Vertices are
  remapped to dense `uint16_t` indices, deduplicated per chunk. A new chunk
  starts on a triangle boundary when the vertex or primitive limit would be
  exceeded.
- Chunks keep their batch's texture and clip. Batches never merge, and
  zero-index batches are skipped. Each chunk is one
  `DrawIndexedPrimitive(D3DPT_TRIANGLELIST)` from `D3DPOOL_DEFAULT` dynamic
  buffers, refilled with `D3DLOCK_DISCARD`.

Unit tests split 70,002 vertices into 65,535 + 4,467 with all 23,334
triangles kept. They also cover vertex and primitive limits, deduplication,
degenerate triangles, negative `base_vertex`, invalid limits and batch
order. Natively, a 70,002-vertex packet draws its last triangle correctly.

## Errors

| Status | Returned when |
| --- | --- |
| `invalid_argument` | null device or packet, bad or mismatched target, target on another device |
| `invalid_packet` | `validate_packet` fails |
| `unsupported` | non-HAL device, missing caps, format or event query, target format/MSAA/usage, oversized texture |
| `busy` | three submissions unretired (`render`; `collect` after polling) |
| `device_lost` | lost device, reset pending, earlier query failure, `Reset` not complete |
| `invalid_frame` | `after_reset` without `before_reset` |
| `capacity` | chunk limits below 3 vertices / 1 primitive, allocation failure |
| `backend_failure` | any other failed D3D9 call or shader compilation |

## Common conformance suite

`tests/conformance/d3d9_backend.cpp` runs as CTest
`wui-conformance-d3d9-hardware` in the `win-d3d9-*` and `win-all-*`
presets. D3D9 has no WARP, so it runs on HAL only (default adapter). It
renders into a `ColorFill`-cleared `A8R8G8B8` target inside a scene and
reads back with `GetRenderTargetData`. Recreate is a real device `Reset`
between `before_reset` and `after_reset`. The D3D9 debug runtime is
unavailable on Windows 10+, so D3D9 output is never proven debug-clean. The
suite logs the debug checks as `SKIP`.

Against the D3D11 WARP reference, D3D9 is within tolerance in all 88 cases,
with worst max channel diff 2 on an RTX 2080 Ti. Three frames are accepted
before `busy`, and re-renders after `Reset` are identical. Details are in
`docs/validation/d-backend-conformance.md`. The comparison test needs
D3D11, so D3D9 is compared only in `win-all-*`.

## Untested items

- Physical device loss. Only the `before_reset` gate is exercised, never a
  lost device or a failed `Issue`/`GetData`.
- Debug-clean output, because no D3D9 debug runtime exists on Windows 10+.
- `X8R8G8B8` targets (accepted, never rendered), `IDirect3DDevice9Ex` and
  non-default adapters. Every test device is windowed with
  `D3DCREATE_SOFTWARE_VERTEXPROCESSING | D3DCREATE_FPU_PRESERVE`.
- `MaxPrimitiveCount` or small `MaxVertexIndex` splits on a real device.
  Only unit tests and synthetic caps cover them.
- A D3D9-specific scissor-snap test. Only the shared helper's unit test
  and the conformance suite cover it.
- `caller_restores` bindings other than RT0 and stream/index, and native
  texture release after `collect`.
